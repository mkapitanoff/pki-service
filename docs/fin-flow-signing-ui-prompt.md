# Промпт для Fin Flow: доработка UI под новый асинхронный контракт подписания Chandra

## Контекст

Chandra (PKI-сервис подписания) перешла на асинхронную модель: `/sign/complete` теперь
возвращает `status: "signed"` **сразу**, как только подпись криптографически подтверждена
NCANode — не дожидаясь сборки итогового PDF (QR-штамп + Лист подписей) и его выгрузки в S3.
Сборка и выгрузка идут в фоне, обычно секунды, но фронт больше не может считать, что после
успешного ответа `/sign/complete` файл готов к скачиванию.

**Это правило одинаково для всех интеграторов Chandra, не доработка под Fin Flow конкретно** —
описано в `docs/integration.md` §3.1 и `docs/openapi.yaml`.

На скриншоте текущего состояния видно: документы показывают бейдж «Загружено» и активную
кнопку «Скачать» без какого-либо статуса именно **подписания** — непонятно, идёт ли ещё
процесс, подписан ли документ уже, готов ли файл. Это и нужно исправить.

## Что изменилось в API (справочно)

`POST /api/v1/sign/complete` — ответ на документ теперь:
```json
{ "doc_id": "…", "name": "…", "status": "signed" }
```
Поля `s3_key` в этом ответе больше нет — оно появляется только через `/sign/status`, и только
когда файл реально готов.

`GET /api/v1/sign/status/{session_id}` — на каждый документ:
```json
{
  "doc_id": "…",
  "name": "…",
  "state": "SIGNED",           // PENDING|FETCHING|READY|SIGNING|SIGNED|UPLOADING|UPLOADED|FAILED
  "verify_url": "https://pki.fin4b.kz/verify/…",  // появляется с state=SIGNED
  "s3_key": "…",               // появляется ТОЛЬКО при state=UPLOADED
  "error_code": "…",           // при FAILED: FETCH_FAILED|UPLOAD_FAILED|SIGNING_FAILED|
                                //             POST_PROCESSING_FAILED|TARGET_URL_EXPIRED
  "error": "…"
}
```

Смысл состояний:
- `SIGNED` — подпись юридически завершена. Файл ещё собирается/выгружается в фоне.
- `UPLOADING` — то же самое, идёт сборка/выгрузка (для пользователя визуально не отличается от SIGNED).
- `UPLOADED` — файл готов, лежит в S3 клиента (`s3_key` заполнен). **Только теперь можно скачивать.**
- `FAILED` (+`error_code: POST_PROCESSING_FAILED`) — фоновая сборка/выгрузка не смогла завершиться
  после нескольких попыток. Это терминально — нужно показать ошибку.
- `FAILED` (+`error_code: TARGET_URL_EXPIRED`) — presigned URL для выгрузки в наш S3 истёк раньше,
  чем закончилась обработка. Восстановимо: бэкенд Fin Flow должен вызвать
  `PATCH /api/v1/sign/refresh-urls` с новым `target_url` для этого документа — Chandra
  автоматически повторит выгрузку без пересборки PDF.

## Что нужно изменить на фронте

### 1. Модалка процесса подписания

Сейчас модалка, судя по всему, закрывается/показывает успех сразу по ответу `/sign/complete`.
Нужно:
- После `succeeded` в ответе `/sign/complete` — не закрывать модалку сразу. Показать per-document
  статус (`SIGNING` → `SIGNED`/`UPLOADING` → `UPLOADED` или `FAILED`) и начать поллинг
  `GET /sign/status/{session_id}` (интервал ~2–3 сек).
- Пока хотя бы один документ в состоянии `SIGNING`/`SIGNED`/`UPLOADING` — показывать
  прогресс/спиннер с текстом вроде «Документ подписан, готовим файл…» (НЕ «Ошибка» и НЕ
  «Готово» — именно промежуточное состояние).
- Остановить поллинг, когда все документы сессии дошли до терминального состояния
  (`UPLOADED` или `FAILED`) — это соответствует `session.status: completed | failed`.
- При `FAILED` — показать ошибку конкретного документа (`error`/`error_code`), не блокировать
  весь список из-за одного упавшего документа.

### 2. Страница со списком документов (как на скриншоте)

Для каждого документа, прошедшего через Chandra (согласия, анкета и т.п. — не путать с
документами, которые клиент просто загрузил на портал и они не подписываются):

- **Добавить бейдж статуса подписания**, отдельный от текущего «Загружено» (который, судя по
  всему, про факт загрузки на портал, а не про факт подписания):
  - `SIGNED` / `UPLOADING` → бейдж «Подписан» (можно добавить мелкий индикатор
    «файл готовится», если хочется показать прогресс, но текст «Подписан» уже корректен)
  - `UPLOADED` → бейдж «Подписан» без дополнительных пометок — полностью готово
  - `FAILED` → бейдж «Ошибка подписания» с кратким текстом причины
  - до `SIGNED` (`PENDING`/`FETCHING`/`READY`/`SIGNING`) — «В процессе»/спиннер

- **Кнопка «Верифицировать» / «Проверить подпись»** — ссылка на `verify_url`. Активна, как
  только `state` достигает `SIGNED` (ждать `UPLOADED` не нужно — страница проверки не зависит
  от готовности скачиваемого файла).

- **Кнопка «Скачать»**:
  - Неактивна (задизейблена, с тултипом «Файл готовится, доступно через несколько секунд») —
    пока `state ≠ UPLOADED`.
  - Активна и рабочая — только когда `state == UPLOADED` **и** `s3_key` непустой.
  - При `state == FAILED` с `error_code == POST_PROCESSING_FAILED` — кнопку не показывать вовсе
    или показывать в виде «Недоступно», без ретрая с фронта (это терминально на бэкенде).

- **Поллинг на этой странице**: если на странице есть документы не в терминальном состоянии
  (`UPLOADED`/`FAILED`), поллить `/sign/status` в фоне (например, раз в 5 сек), чтобы бейджи и
  кнопка «Скачать» обновлялись сами, без перезагрузки страницы пользователем.

### 3. Обработка `TARGET_URL_EXPIRED`

Это восстановимая ошибка, но чинится на бэкенде Fin Flow (сгенерировать новый presigned
`target_url` и вызвать `PATCH /api/v1/sign/refresh-urls`), не на фронте. На фронте в этом
случае можно показать нейтральный текст «Обрабатываем документ, это может занять больше
времени» вместо явной ошибки, если бэкенд планирует автоматически повторить выгрузку; либо
явную ошибку с кнопкой «Повторить», которая триггерит бэкенд-эндпоинт повторной выгрузки —
как решите на своей стороне.

## Итоговый чек-лист

- [ ] Модалка подписания поллит `/sign/status` до терминального состояния всех документов,
      не закрывается по одному лишь ответу `/sign/complete`.
- [ ] На странице документов — отдельный бейдж статуса подписания (не путать с «Загружено»).
- [ ] Кнопка «Верифицировать» на `verify_url`, активна с `state=SIGNED`.
- [ ] Кнопка «Скачать» активна только при `state=UPLOADED` и непустом `s3_key`.
- [ ] `FAILED` документы показывают причину, не блокируют остальные документы сессии.
- [ ] Фоновый поллинг статуса на странице документов, пока есть незавершённые документы.
